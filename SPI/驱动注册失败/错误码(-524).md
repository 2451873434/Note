# Flash驱动注册失败——错误码(-524)

## 问题现象

​	使用6.6版本内核在`D3000M`上测试`spi-iop`和`spi`直通驱动时，出现以下报错：

```
acpi PHYT8009:00: GPIO: looking up 0 in _CRS
spi-nor spi-PHYT8009:00 using ACPI '\_SB.SPI0.FLAS' for 'reset' GPIO lookup
acpi PHYT8009:00: GPIO: looking up reset-gpios
acpi PHYT8009:00: GPIO: looking up reset-gpio
spi-nor spi-PHYT8009:00: using lookup tables for GPIO lookup
spi-nor spi-PHYT8009:00: No GPIO consumer reset found
spi-nor: probe of spi-PHYT8009:00 failed with error -524
```

## 问题原因

​	这里很容易被第1-6行打印信息误导，这些信息其实不是报错信息，而是`dev_dbg()`函数打印的设备调试信息。这些信息由`spi_nor_hw_reset()`函数中调用的下层级函数打印，而`spi_nor_hw_reset()`函数又是在flash驱动注册时调用，所以就很容易错误的认为错误是出现在该函数中。其实一直跟踪`spi_nor_hw_reset()`函数往下找不难发现，其下层函数的错误码返回值只有`-ENOENT(-2)`，`-ENOMEM(-12)`，`-EINVAL(-22)`和`-EPROBE_DEFER(-517)`，而没有错误码`-ENOTSUPP(-524)`。根据最后一行报错信息来看，返回的错误码是`-ENOTSUPP(-524)`，所以可以推断错误不是出现在`spi_nor_hw_reset()`函数中。

​	要想定位到出错位置，可以在`spi`的`flash`驱动相关的各文件中查找错误码`-ENOTSUPP(-524)`，然后在这些地方分别加上自定义的打印，再重新编译内核进行测试，根据打印信息定位出出错的具体位置和原因。

​	在本例中，出错位置在`spi_mem_exec_op`函数，原因为在检查传输信息的位宽不符合设置的传输协议`proto`，如传输信息的指令和数据位宽均为1，但是由于系统采用`UEFI`模式启动，没有初始化`spi->tx_proto`和`spi->rx_proto`，导致其值为0，因此出错。

​	笔者发现，`spi`的`flash`驱动注册返回错误码`-ENOTSUPP(-524)`时最有可能出错的位置就是在`spi_mem_exec_op()`函数检查传输信息的位宽是否符合传输协议处。因此如果下次遇到相似的报错信息，可以优先考虑该原因。

## 解决方法

​	初始化`spi->tx_proto`和`spi->rx_proto`参数。

> 这两个参数是笔者在对`spi`的`flash`添加1-1-4和1-4-4模式功能时往`struct spi_device`结构体添加的自定义参数。
