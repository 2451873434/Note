# 应用场景

​	1、当正在`dev`分支上开发某个项目，这时有其他事情需要切换到其他分支去处理，但是正在开发的内容只是完成一半，还不想提交，这时可以用`git stash`命令将修改的内容保存至堆栈区，然后顺利切换到其他分支做其他事情，完成之后再切回`dev`分支，从堆栈中恢复刚刚保存的内容。

​	2、由于疏忽，本应该在`dev-1`分支开发的内容，却在`dev-2`分支上进行了开发。可以用`git stash`将内容保存至堆栈区，切回到`dev-1`分支后，再次恢复内容即可。

​	总的来说，`git stash`命令的作用是将目前还不想提交的但是已经修改的内容进行保存至堆栈中，后续可以在某个分支上恢复出堆栈中的内容。这也就是说，`stash`中的内容不仅仅可以恢复到原先开发的分支，也可以恢复到其他任意指定的分支上。

# 常用`git stash`命令

| 命令                        | 说明                                                         |
| --------------------------- | ------------------------------------------------------------ |
| `git stash save "message"`  | 指向存储时，添加备注信息，方便查找<br />只有`git stash`也行，但是查找时不方便识别 |
| `git stash list`            | 查看`stash`中有哪些存储                                      |
| `git stash show stash@{0}`  | 显示某个存储做了哪些改动<br />只有`git stash show`默认显示第一个存储的改动 |
| `git stash apply stash@{0}` | 应用某个存储，但不会把存储从存储列表中删除<br />只有`git stash apply`默认应用第一个存储 |
| `git stash pop stash@{0}`   | 应用某个存储，把存储从存储列表中删除<br />只有`git stash pop`默认应用第一个存储 |
| `git stash drop stash@{0}`  | 丢弃某个存储                                                 |
| `git stash clear`           | 删除所有存储                                                 |
| `git stash branch`          | 从最新的`stash`创建分支                                      |
