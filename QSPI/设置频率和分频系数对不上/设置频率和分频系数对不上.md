# 设置频率和分频系数对不上

## 问题现象

当qspi控制器的时钟频率为200MHZ，设备树中设置片选0的频率为12.5MHZ时，进入系统后，通过使用RW工具读取控制器寄存器信息发现分频系数并不是16分频，如下：

```c
// 设备树描述如下
sysclk_200mhz: clk200mhz {
    compatible = "fixed-clock";
    #clock-cells = <0>;
    clock-frequency = <200000000>;
};

qspi: spi@28004000 {
    compatible = "phytium,qspi-nor";
    reg = <0x0 0x28004000 0x0 0x1000>,
    	  <0x0 0x0 0x0 0x10000000>;
    reg-names = "qspi", "qspi-mm";
    clocks = <&sysclk_200mhz>;
    #address-cells = <1>;
    #size-cells = <0>;
    status = "okay";
    flash@0 {
        compatible = "jedec,spi-nor";
        reg = <0x0>;
        spi-max-frequency = <12500000>;
    };
};
```

```shell
# OS下读取寄存器值如下
root@ft:/home/ft# ./rw -r 4 0x28008004
[0000000028008004]: 03000008
```

不难看出，虽然设备树设置的是16分频系数，但是实际上看寄存器发现`bit[2:0]`对应的分频系数为128，这显然是不对的。

## 原因

通过在内核的qspi控制器驱动源码中有关计算分频系数和设置分频系数时加打印。发现在计算分频系数`flash->clk_div`时其值为16，是正常的。而在设置分频系数`cmd |= flash->clk_div & QSPI_RD_CFG_RD_SCK_SEL_MASK`时，宏`QSPI_RD_CFG_RD_SCK_SEL_MASK`的值不对，`rd_cfg`寄存器的分频系数为`bit[2:0]`，而该宏的值为`0x3`，而不是`0x7`，显然不对。

同样的，`wr_cfg`和`cmd_cfg`也是一样的情况，`QSPI_WR_CFG_WR_SCK_SEL_MASK`和`QSPI_CMD_PORT_SCK_SEL_MASK`宏均为`0x3`，而不是`0x7`，显然不对。

## 解决方法

修改内核代码中有关以下三个宏的值。

```c
// 错误的宏定义
#define QSPI_RD_CFG_RD_SCK_SEL_MASK	(0x3 << QSPI_RD_CFG_RD_SCK_SEL_SHIFT)
#define QSPI_WR_CFG_WR_SCK_SEL_MASK	(0x3 << QSPI_WR_CFG_WR_SCK_SEL_SHIFT)
#define QSPI_CMD_PORT_SCK_SEL_MASK	(0x3 << QSPI_CMD_PORT_SCK_SEL_SHIFT)

// 正确的宏定义
#define QSPI_RD_CFG_RD_SCK_SEL_MASK	(0x7 << QSPI_RD_CFG_RD_SCK_SEL_SHIFT)
#define QSPI_WR_CFG_WR_SCK_SEL_MASK	(0x7 << QSPI_WR_CFG_WR_SCK_SEL_SHIFT)
#define QSPI_CMD_PORT_SCK_SEL_MASK	(0x7 << QSPI_CMD_PORT_SCK_SEL_SHIFT)
```
