# 内核镜像存放在flash中出现`Bad Data CRC`

## 问题现象

​	将固件（`9MB`）、内核镜像（`20MB`）、文件系统（`23MB`）均放在`qspi`控制器下的`flash`中，根据所放文件的大小将`flash`空间按如下分配：固件（`0-15MB`），内核镜像（`15-40MB`），文件系统（`40-64MB`）。可以看出，至少得用`64MB`大小的`flash`。而当笔者将所有文件打包成一个`bin`文件，并且烧录到flash中后，在`uboot`到`OS`阶段出现如下情形。

```shell
## Booting kernel from Legacy Image at f00000 ...
   Image Name:   
   Image Type:   AArch64 Linux Kernel Image (uncompressed)
   Data Size:    19735104 Bytes = 18.8 MiB
   Load Address: 90000000
   Entry Point:  90000000
   Verifying Checksum ... Bad Data CRC
```

## 原因

​	不难看出，`0xf00000`就是内核镜像存放的起始地址（`15MB`），所以基本可以确认的是`15-40MB`这段空间的数据内容不是内核镜像的文件数据，或者内核镜像文件本身存在问题（经检查内核镜像没有问题，而且这种情况一般出现的可能性很小，本文仅讨论前者）。

​	笔者在`uboot`阶段检验`15-40MB`这段空间的数据与内核镜像的文件数据，发现两者并不相同，如下：

```shell
# 15-40MB空间数据
D3500# md.l 0x1000000
01000000: 0001 0001 0001 0001
01000004: 0001 0001 0001 0001
......

# uImage文件数据
......
00100000: e856 f093 246e a901
00100004: b872 974c 010a 005e
......
```

> 注意：flash中存放内核镜像的起始地址是`15MB`（`0xf00000`），所以flash的地址为`0x1000000`存放的是内核镜像的`0x100000`处的数据。
>
> `0x100000 + 0xf00000 = 0x1000000`

​	最初怀疑是在打包固件，内核镜像，文件系统成`bin`文件时出错了，所以检查`bin`文件中`0x1000000`处的数据，发现该处数据和内核镜像的数据相同。

​	接着怀疑是将`bin`文件烧录到flash时出错，所以用烧录器去重新读取`flash`中`0x1000000`处的数据，发现该处数据和内核镜像的数据也相同。

​	那最后只剩一种可能，就是`uboot`下读取`flash`的`0x1000000`处的数据时读取出错，即`flash`中的数据是对的，但是读出来的数据是错的。检查后发现`qspi`控制器的`00`寄存器的值为默认值0，即默认为一个`16MB`的`flash`。而实际上使用的是一个`64MB`的`flash`。同时qspi控制器的04寄存器的`rd_cmd[31:24]`的默认值为`03h`，其为三字节地址的读指令，而`flash`的大小为`64MB`，想要正常读取需要用到四字节地址的读指令。

## 解决方法

​	在进入`uboot`后，配置`qspi`控制器的`00`寄存器为正常值。在本文中配置其值为`0x4`，代表一个`64MB`的`flash`。同时也需要配置qspi控制器的04寄存器的值。

```shell
D3500# mw.l 0x18006000 0x4
D3500# mw.l 0x18006004 0x13080009
```
