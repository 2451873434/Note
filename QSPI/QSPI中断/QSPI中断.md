# `QSPI`中断

| 中断             | 描述                                                       |
| ---------------- | ---------------------------------------------------------- |
| `flash_timeout`  | flash超时，和`wip`同时使用，flash操作超时时会触发该中断    |
| `illegal_access` | 在读写`buf`过程中，有非法访问时会触发该中断                |
| `qspi_rd`        | 连续读使能，只能用于间接读数据，在读ID时无法触发该中断     |
| `wbuf_done`      | 写`buf`完成中断，在控制器将`buf`中数据发送完成后触发该中断 |
| `wip`            | `wip`中断，无需上层发送`0x05`指令去确定`wip`位             |



## `wip`中断

​	理论上`6.6`版本内核中，发送`0x05`指令去确认`wip`状态位的逻辑是在`core`层做的，所以需要改动`core`层代码才能用上该功能，但是一般不允许随意改动`core`层代码。

​	存在如下情况下可以使用`wip`中断：在`qspi`控制器驱动层直接写函数最后手动增加使用`wip`中断的代码。在此种情况下，判断`wip`完成会在`qspi`控制器驱动层完成，然后返回到`core`层后，`core`层会额外发送一次`0x05`指令去确认状态。所以依然会多一次`0x05`的指令。

## `wbuf_done`中断

这个可以做，但是个人感觉没必要做。因为在写`buf`之后依然会发送`0x05`指令确认写完成状态。

## `qspi_rd`中断

由于该中断只能用于间接读数据，而如`0x9f`指令在读`ID`时也会用到`0x10`寄存器，而`0x9f`指令无法触发该中断，并且指令都是由`core`层下发，`qspi`驱动层无法区分。目前采用的方式是通过读数据长度来判断是否使用该中断，以此方式来过滤`0x9f`指令。

## `illegal_access`中断

和`wbuf_done`中断同时使用

## `flash_timeout`中断

和`wip`中断同时使用
