# 4.19和5.15的qspi设备树描述差异

## 问题现象

使用4.19内核镜像和设备树在E2000上测试qspi，发现驱动和设备无法匹配。而使用相同设备树与5.15及以上版本的内核镜像，则能够正常识别。如下：

```
现象1：无报错信息，无qspi驱动打印信息

现象2：有如下报错信息
phytium-quadspi 28008000.qspi: unable to setup flash chip
phytium-quadspi: probe of 28008000.qspi failed with error -20
```

## 原因

现象1的原因：4.19内核的qspi控制器的`compatible = "phytium,qspi"`，而5.15内核的qspi控制器的`compatible = "phytium,qspi-nor"`。当将5.15内核使用的设备树给4.19内核使用时，设备和驱动的`compatile`不同导致无法进行匹配，因此没有相关打印信息。

现象2的原因：4.19内核使用的设备树的qspi控制器下的flash子节点需要描述`spi-rx-bus-width`，而不需要描述`compatible`，而5.15内核使用的设备树的qspi控制器下的flash子节点需要描述`compatible`，而可以不描述`spi-rx-bus-width`。当将5.15内核使用的设备树给4.19内核使用时，由于设备树中flash节点上没有`spi-rx-bus-width`描述而报错。

## 解决方法

按照如下示例去编写4.19和5.15内核使用的设备树的qspi相关节点描述：

```
# 4.19内核使用的设备树的qspi节点描述
qspi@28008000 {
	compatible = "phytium,qspi";
	reg = <0x0 0x28008000 0x0 0x1000 0x0 0x0 0x0 0xfffffff>;
	reg-names = "qspi","qspi_mm";
	clocks = <0xc>;
	status = "okay";
	
	flash@0 {
		reg = <0x0>;
		spi-max-frequency = <0xb71b00>;
		spi-rx-bus-width = <0x1>;
	};
};

# 5.15内核使用的设备树的qspi节点描述
qspi@28008000 {
	compatible = "phytium,qspi-nor";
	reg = <0x0 0x28008000 0x0 0x1000 0x0 0x0 0x0 0xfffffff>;
	reg-names = "qspi","qspi_mm";
	clocks = <0xc>;
	status = "okay";
	
	flash@0 {
		compatible = "jedec,spi-nor";
		reg = <0x0>;
	};
};
```

> 注意：5.4版本内核介于4.19和5.15之间，5.4版本内核的qspi控制器驱动和5.15内核相同，flash驱动和4.19内核相同。笔者没有仔细看过5.4版本内核的代码，本文对于5.4内核的设备树中qspi描述不做讨论。
