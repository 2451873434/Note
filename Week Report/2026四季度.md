任务名称：D3000M部分内存保留方案
时间计划：20260915-20261130

3、华为反馈目前采用的保存寄存器信息的方式欠妥 ，建议每个模块的寄存器信息都以一个单独的文件显示。由于目前pstore子系统中日志文件名与设备树节点中xxx-size（如blackbox-size）属性强相关，所以有三种方案来实现：

* 为每个模块分配独立的ramoops持久化区（需要扩大/调整blackbox预留内存，并修改分区配置），即在设备树中为每个模块加入对应的xxx-size属性，该方案的代码变动不大，但会导致设备树的ramoops节点臃肿，如下：
  * ramoops@0 {
    	no-map;
    	compatible = "ramoops";
    	reg = <l 0x0 0x8000000>;
    	record-size = <0x100000>;
    	blackbox-size = <0x100000>;
    	uart0-size = <0x1000>;
    	uart1-size = <0x1000>;
    	...
    };
* 为所有模块分配一个独立的ramoops持久化区，在设备树中为所有模块加入一个统一的register-size属性，该方案会把所有寄存器信息保存到一个单独的register-ramoops-0文件中，设备树节点如下。该方案的寄存器信息查看依旧不方便，应该也不是华为想要的效果。
  * ramoops@0 {
    	no-map;
    	compatible = "ramoops";
    	reg = <l 0x0 0x8000000>;
    	record-size = <0x100000>;
    	blackbox-size = <0x100000>;
    	register-size = <4000000>;
    };
* 在现有的blackbox区中存一份数据，启动读取时按寄存器拆成UART0-ramoops-0等独立文件。该方案不需要修改现有的设备树描述，但是代码变动较大。

后续计划：
计划采用第三种实现方式，代码编写中。
